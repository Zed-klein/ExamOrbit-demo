# 考点雷达

> 输入你的考点和考场楼栋，输出「住哪家最稳、那天几点出门、走哪条路、会不会淋雨」。

## 一句话

**「考点」不是一个点，是一个几公里见方的封闭园区，而且你只能从指定的门进去。**

实测证据：从同一家酒店出发到浙江大学紫金港校区的两个考场——

| 目的地 | 直线 | 真实步行 |
|---|---|---|
| 北3教学楼（走北2门） | 354 m | **516 m / 6.1 分钟** |
| 东1教学楼（走东2门） | 1558 m | **2329 m / 28.7 分钟** |

而订票平台给这家酒店的标注是「浙江大学（紫金港校区）— 直线距离 958 米」。

**同一个「958 米」，两种人生。**

## 怎么打开

**方式一（最简单）**：直接双击 `index.html`。

> 实测可用：`file://` 下地图瓦片、地点检索、路线规划、天气全部正常。
> 唯一会看到的两条红色报错来自百度自己的埋点 `miao.baidu.com`（浏览器拦截
> `file://` 的跨域埋点），**不影响任何功能**，忽略即可。

**方式二**：起一个静态服务器（定位按钮需要 localhost 或 HTTPS 才能用）：

```bash
cd 项目结果
python3 -m http.server 8899
# 浏览器打开 http://127.0.0.1:8899/index.html
```

无需安装、无需构建、无需后端。

### 分享给别人测试

把 `分享包/` 整个目录（或 `考点雷达-分享包.zip`）发给对方，解压后双击 `index.html` 即可。

⚠️ **必须发整个目录**，不能只发 `index.html` —— 它依赖同级的
`config/`、`src/`、`data/`。只发一个 html 文件会白屏。

⚠️ **额度提示**：内置 AK 的「地点检索」是 **100 次/天**（每搜索一个新考点消耗 1 次），
用完后可以点右上角 ⚙ 换成自己的百度 AK。逆地理编码、路线规划额度充足
（分别 5000/日），正常测试碰不到。

## 功能

| 页签 | 内容 |
|---|---|
| **① 考点选择** | 4 个已核实考点；可选到**具体考场楼栋 / 指定校门**（不选楼栋，所有时间都是错的） |
| **② 行程可视化** | 按**真实步行时间**排序的住宿榜（默认 5 家，可展开）、多色真实路线、☔ 淋雨推演滑块、服务点图层 |
| **③ AI 辅助出行** | **基于服务点的综合路线推荐**：住哪 + 几点出发 + 走哪条 + 沿途能办什么事。自带 API（BYOK），未配置时由本地规则引擎回答 |

### 核心亮点

- **打假直线距离**：住宿榜按百度真实步行分钟排序，直线距离加删除线做对照
- **真实路线数据**：24 条步行路线由百度算路生成，含 33+ 个路径点与逐步转向
  （如「右转进入章明巷」「沿申花路走 20 米，左转过斑马线」）
- **路线即身份**：每家住宿一个专属颜色，列表名称颜色 = 地图路线颜色；点开显示详细转向
- **校内要素**：落在校内的住宿/服务点不做路线规划，直接标记（校门凸包判定）
- **淋雨推演**：基于**真实降水**（16 天内取预报，更远取近 5 年同日气候概率）。
  沿真实路径累计距离算 ETA，在降水序列上插值；**湿段锚定考点端**
- **真实路网等距多边形**（参考「15 分钟生活圈」）：以**校门**为中心，
  朝非校内方向发射射线、沿真实路径取「走满预算」的落点连成多边形。
  步行 1km / 骑行 2km / 公交 3km / 驾车 5km 随出行方式切换，
  **只有范围内的服务点才显示**；多边形不可用时降级为半径圆并**明确标注**
- **统一以校门为目的地**：不再细分教学楼，每家住宿自动匹配**最近的校门**
- **服务点图层**：283 个真实 POI（打印店/文具店/药店/派出所/医院/停车场）
- **四种出行方式全部真实**：步行/骑行/驾车/公交均由百度算路生成（估算值带 `~` 标注）
- **卫星影像**：右上角一键切换「标准 / 卫星」（百度卫星实拍图）
- **白天 / 黑夜模式**：右上角一键切换
- **顶层环境条**：IP 定位城市 + 当前时间 + 实时天气
- **考试锚点**：高考 / 考研 / 考公 / 四六级 四个预设 + 完全自定义（名称/年月日/起止时间）
- **考场楼栋粒度**：把官方《考生须知》结构化成数据，标注依据年度

## 技术形态

**一个纯静态网站**，无服务端。

| 依赖 | 用途 | 配额 |
|---|---|---|
| 百度地图 JS API（BMapGL） | 底图、标记、路线、定位 | 地图渲染**不计次**；定位 5,000/日 |
| `data/snapshot.js` 快照 | 4 个考点全量数据 | 运行时**零 API 调用** |
| `localStorage` | 记住上次考点、配额计数 | — |

### 配额设计（本作品的技术重点之一）

百度给个人开发者的**地点检索只有 100 次/日，超出当天禁用且不可恢复**，且换 AK 无效。

我们的解法是**把配额消耗全部推到构建期**：

```text
构建期（一次性）
  调用真实步行算路，把路线几何写进快照
        ↓
运行期（零百度 API 调用）
  地图渲染 / 覆盖物 / 淋雨推演 / 行程清单 ... 不计次
  只有「定位」计次，且经四层守卫：
    · 本地计数    · 90% 熔断（避免触发不可恢复的禁用）
    · 结果缓存    · 3 QPS 串行队列（官方并发上限就是 3）
```

**结果：4 个演示考点零 API 调用、断网可演示。**

### 离线兜底

地图加载失败或超时 15 秒 → 自动切回内置示意图，其余功能全部照常。
**现场断网也不会白屏。**

## 数据来源与诚实边界

| 数据 | 来源 |
|---|---|
| 路线几何、步行时长 | 百度地图步行路线规划（构建期） |
| 考点、考场楼栋、指定校门 | 各校官方《考点考生须知》（**上一年度**，界面已标注） |
| 降水 | Open-Meteo（免 Key，前端直连，零百度配额） |
| 服务点 POI | 百度地点检索（**构建期**一次性落盘，运行时零调用） |
| 城市定位 | 百度 IP 定位（`LocalCity`，精度城市级） |
| 坐标精确定位 | 百度**地理编码**（5,000/日。校区中心、考场楼栋、住宿全部按地址反查） |
| 坐标转换 | WGS84 → BD09，已与标准实现逐位校验（差异 < 1e-12） |

✅ **路线几何、转向步骤、服务点均为百度 API 真实生成**（构建期落盘）。
⚠️ 其中 12 家住宿坐标由百度地点检索校正，另 12 家因匹配到同名分店被自动回退为推算值
（界面标注为「估算」）。**校区中心点已全部校正为真实坐标。**
最终精确化建议用百度**坐标拾取器**人工复核。

> 这条边界是刻意保留的：在「步行 6 分钟 vs 28 分钟」这个核心叙事上，
> 坐标差几百米会直接毁掉结论，所以我们宁可标注清楚，也不假装精确。

## 文件结构

```text
index.html            主应用（UI + 地图接入 + 主题 + 环境条）
config/ak.js          百度地图 AK 配置（唯一真源）
src/quota.js          配额守卫：发起即计数 / 熔断 / 缓存 / 3QPS 串行队列
src/baidu-map.js      地图适配层：BMapGL、渲染、淋雨染色、坐标转换、主题
src/weather.js        Open-Meteo 天气：实况 / 逐小时预报 / 历史气候概率
data/snapshot.js      考点快照（script 标签加载，file:// 双击可用）
data/snapshot.json    同上，JSON 备用副本
```

> AI 辅助出行**不内置任何 API Key**。点右上角 ⚙ 填入自己的
> Base URL / API Key / 模型名即可（DeepSeek、智谱、通义、豆包、Kimi、硅基流动
> 均已实测支持浏览器直连）。未配置时由本地规则引擎回答，功能不缺失。
